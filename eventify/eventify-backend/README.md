# Eventify

Бронирование билетов на события. Backend разбит на несколько сервисов
(Spring Boot, Java 21)

## Сервисы

- **auth-service** (8081) — регистрация, логин, выпуск JWT
- **event-service** (8082) — CRUD событий, количество доступных билетов
- **booking-service** (8083) — брони: создание, подтверждение, отмена, просрочка неподтверждённых
- **notification-service** (8084) — email, подтверждение почты, напоминания, привязка Telegram
- **telegram** — бот: команды, напоминания, уведомления о статусе брони

У каждого сервиса своя база Postgres, свои миграции Liquibase. Между
сервисами Kafka либо синхронные internal-эндпоинты с аутентификацией по ключу
сервисов.

Общие модули: `common` (JWT-фильтр),
`service-security` (internal API-ключ), `kafka-contracts` (общие классы
для Kafka-сообщений), `outbox-support` (реализация outbox-паттерна),
`event-api` (общие DTO для вызывающих event-service).

Фронтенд — `booking-ui/`, React + TypeScript.

## Архитектурные решения

Запись в БД и публикация Kafka-события выполняются в одной транзакции
(outbox pattern). Отдельные сервисы с заданным интервалом публикуют накопленные
события в Kafka, поэтому временная недоступность
брокера не приводит к потере данных.

Дедупликация Kafka-сообщений учитывает разницу между «то же сообщение
доставлено повторно» и «то же действие выполнено снова». При необходимости
используется `operationId` (UUID), генерируемый на источнике в
момент действия.

Письма не отправляются напрямую из Kafka-consumers: сначала запись
помещается в очередь (`pending_emails`), а отправку через
SMTP выполняет отдельный сервис с заданным интервалом.
Для адресов, которые сервер отклоняет сразу, установлен предел в 5 попыток 
— по его достижении отправка прекращается, а не повторяется бесконечно.

У Telegram-бота собственная локальная таблица подписок, не зависящая от
доступности notification-service во время работы. Интервал напоминаний
в Telegram задаётся независимо от интервала для email.

## Запуск

```bash
cp .env.example .env
# заполнить .env
docker compose up -d --build
```

Приложение — `http://localhost:8080` (через nginx), Kafka UI —
`http://localhost:8090`.

Фронтенд отдельно:

```bash
cd booking-ui
npm install
npm start
```
